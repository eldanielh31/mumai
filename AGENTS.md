# Continuidad del proyecto Daniel Proyecto Final

Solicitud persistente de Daniel: documentar problemas, cambios, decisiones y pruebas para reutilizarlos en informes; mantener el proyecto en un repositorio privado de GitHub y subir los avances autorizados al terminar cada entrega.

- Leer `docs/README.md` y el estado más reciente antes de modificar el proyecto. Respetar el plan original y distinguir fechas previstas de fechas reales.
- Conservar auditorías y evidencias históricas. Crear una carpeta nueva por revisión; no reescribir un informe antiguo para atribuirle correcciones posteriores.
- Registrar los cambios de comportamiento, causa, solución, requisitos relacionados, pruebas y pendientes. No inventar horas reales, datos de cámara, aceptación, porcentajes de avance ni pruebas que no se ejecutaron.
- Ejecutar verificaciones proporcionales al cambio y guardar la evidencia pertinente. Los ejemplos sintéticos deben estar identificados como tales. Daniel autorizó explícitamente versionar todos los videos de data/input/, incluidos los del motor, mediante Git LFS.
- Guardar entregas coherentes en commits. Cuando GitHub esté conectado y se haya confirmado el remoto privado autorizado, subir los commits y comprobar que el remoto corresponde al commit local. No afirmar publicación basándose solo en un commit o en haber intentado enviar.
- No crear un remoto público, sobrescribir historia remota, introducir credenciales ni publicar grabaciones reales sin autorización específica. Mantener entornos, archivos temporales y data/output/ fuera del repositorio; la autorización de grabaciones se limita a data/input/.
- Si falta autenticación, completar el trabajo local y comunicar exactamente qué conexión falta. No solicitar contraseñas ni tokens por el chat.
- La solicitud de subir avances se aplica al trabajo realizado en las sesiones; no presupone un servicio de sincronización continua ni tareas programadas.
